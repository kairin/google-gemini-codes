Using a GitHub Actions Self-Hosted Runner

This guide explains how to set up and use a self-hosted runner for your project to avoid GitHub-hosted runner costs.

1. Register Your Runner

  1. Go to Settings → Actions → Runners in your GitHub repository.
  2. Click "New self-hosted runner" and follow the instructions for your OS.
  3. When prompted, you can add a custom label (e.g. Linux-Ubuntu).
  4. Start the runner with ./run.sh in the actions-runner directory.

2. Workflow Configuration

Your workflow file should use your custom label:

runs-on: [self-hosted, Linux-Ubuntu]

Example workflow:

name: Build Locally

on:
  workflow_dispatch:

jobs:
  build:
    runs-on: [self-hosted, Linux-Ubuntu]
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: Detect package manager
        id: detect-package-manager
        run: |
          if [ -f "${{ github.workspace }}/yarn.lock" ]; then
            echo "manager=yarn" >> $GITHUB_OUTPUT
            echo "command=install" >> $GITHUB_OUTPUT
            echo "runner=yarn" >> $GITHUB_OUTPUT
            echo "lockfile=yarn.lock" >> $GITHUB_OUTPUT
            exit 0
          elif [ -f "${{ github.workspace }}/package.json" ]; then
            echo "manager=npm" >> $GITHUB_OUTPUT
            echo "command=ci" >> $GITHUB_OUTPUT
            echo "runner=npx --no-install" >> $GITHUB_OUTPUT
            echo "lockfile=package-lock.json" >> $GITHUB_OUTPUT
            exit 0
          else
            echo "Unable to determine package manager"
            exit 1
          fi
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: ${{ steps.detect-package-manager.outputs.manager }}
          cache-dependency-path: ${{ steps.detect-package-manager.outputs.lockfile }}
      - name: Install dependencies
        run: ${{ steps.detect-package-manager.outputs.manager }} ${{ steps.detect-package-manager.outputs.command }}
      - name: Install marked
        run: npm install marked --save
      - name: Build with Astro
        run: ${{ steps.detect-package-manager.outputs.runner }} astro build

3. Running the Workflow

  1. Start your runner with ./run.sh (leave this terminal open).
  2. Go to the Actions tab in your repo and click Run workflow for Build Locally.
  3. The workflow will run on your local/server machine, not on GitHub-hosted infrastructure.

4. Tips

  • You can add more custom labels to target specific runners.
  • Monitor your runner status in Settings → Actions → Runners.
  • Stop the runner with Ctrl+C when not in use.

5. Why Use a Self-Hosted Runner?

  • No GitHub-hosted runner costs for private repos or heavy usage.
  • Full control over the build environment.
  • Can use your own hardware or cloud VM.
