Astro Dynamic Route Param Mapping: Robust Best Practice

Why is this important? Astro requires the param name in params (from getStaticPaths) to match the filename of your dynamic route. If they don’t match, your build will fail.

Centralized Mapping

To keep your code DRY and robust, use a single mapping file for all dynamic route param names. This ensures your static path generation and route files always stay in sync.

// src/utils/routeParamMap.js

export const routeParamMap = {
  blog: 'blogslug',      // for src/pages/blog/[...blogslug].astro
  projects: 'slug',      // for src/pages/projects/[...slug].astro
  // Add more as needed
};

How to Use

  1. Import routeParamMap in your static path generator.
  2. Always use the mapped param name for params in getStaticPaths.
  3. Make sure your dynamic route filename matches the param name.

Reusable Component

Use the RouteParamInfo component below to display this mapping anywhere in your docs or contributor pages.

Route Param Name Example Path
/blog/[...blogslug].astro blogslug /blog/my-post/1
/projects/[...slug].astro slug /projects/my-project/1

Key Takeaway

Never change a dynamic route filename or param name without updating the mapping in routeParamMap.js!
